# Full Stack Open - State Management: Anecdotes Zustand

This project is a new version of the "Anecdotes" application from Part 1 of the Full Stack Open course, rebuilt for the [State Management](https://courses.mooc.fi/org/uh-cs/courses/full-stack-open-state-management) part using [Zustand](https://zustand.docs.pmnd.rs/). The application lets users vote for anecdotes, add new ones, filter the list and delete anecdotes that have no votes. The data is stored in a JSON Server backend and fetched with the Fetch API, the application state lives in Zustand stores, and the interface is styled with Tailwind CSS v4 with light and dark themes.

## ✅ Exercises Overview

During the development of the project in the State Management part, the following tasks were performed.

### 3: Anecdotes, step 1

- Used the project in the `anecdotes` directory as the base of the solution.
- Implemented voting for anecdotes. The number of votes is kept in the Zustand store, and the `vote` action increases the votes of a single anecdote without touching the others.

### 4: Anecdotes, step 2

- Added the ability to add new anecdotes with an `add` action in the store.
- The form stays uncontrolled: the value is read from the form element on submit and the form is reset afterwards.

### 5: Anecdotes, step 3

- Separated the creation of a new anecdote into the `AnecdoteForm` component and the display of the list into the `AnecdoteList` component.
- The components read the data and the actions they need directly from the store, so `App` only composes them.

### 6: Anecdotes, step 4

- Anecdotes are always displayed in descending order by the number of votes.
- The list is sorted with `Array.toSorted`, which creates a sorted copy, so the Zustand state is never mutated.

### 7: Anecdotes, step 5

- Added the `Filter` component and a `filter` value with a `setFilter` action in the store.
- The list shows only the anecdotes whose content contains the filter text, ignoring letter case, and the result is still sorted by votes.

### 8: Anecdotes, step 6

- The anecdotes are fetched from the JSON Server backend (`http://localhost:3001/anecdotes`) when the application starts, using the Fetch API.
- Added the `services/anecdotes.js` module for the HTTP requests and an `initialize` action in the store that saves the fetched anecdotes in the state.

### 9: Anecdotes, step 7

- New anecdotes are saved in the backend with a `POST` request. The `add` action puts the anecdote returned by the server (with the `id` generated by the backend) into the state.

### 10: Anecdotes, step 8

- Voting is saved in the backend with a `PUT` request. The state is updated with the anecdote returned by the server, so the interface shows only saved votes.

### 11: Anecdotes, step 9

- The `Notification` component shows a message for five seconds after voting for an anecdote or creating a new one.
- The notification state lives in a separate Zustand store (`notificationStore.js`). A new notification clears the timer of the previous one, so every message gets its full time.

### 12: Anecdotes, step 10

- Added deleting anecdotes that have zero votes with a `DELETE` request.
- The `delete` button is shown only for anecdotes without votes, and the store checks the number of votes again before the request is sent.

**Example store (simplified):**

```js
import { create } from "zustand";
import { getAll, createNew, update, remove } from "./services/anecdotes";

export const useAnecdoteStore = create((set) => ({
  anecdotes: [],
  filter: "",
  actions: {
    initialize: async () => {
      const anecdotes = await getAll();
      set({ anecdotes });
    },
    add: async (content) => {
      const newAnecdote = await createNew(content);
      set((state) => ({ anecdotes: state.anecdotes.concat(newAnecdote) }));
    },
    vote: async (id) => {
      const anecdote = useAnecdoteStore.getState().anecdotes.find((a) => a.id === id);
      const updated = await update({ ...anecdote, votes: anecdote.votes + 1 });
      set((state) => ({
        anecdotes: state.anecdotes.map((a) => (a.id === id ? updated : a)),
      }));
    },
    setFilter: (filter) => set({ filter }),
  },
}));

export const useAnecdotes = () => useAnecdoteStore((state) => state.anecdotes);
export const useAnecdoteActions = () => useAnecdoteStore((state) => state.actions);
export const useFilter = () => useAnecdoteStore((state) => state.filter);
```

**Example component logic (simplified):**

```jsx
const AnecdoteList = () => {
  const anecdotes = useAnecdotes();
  const filter = useFilter();
  const { vote } = useAnecdoteActions();

  const visibleAnecdotes = anecdotes
    .filter((a) => a.content.toLowerCase().includes(filter.toLowerCase()))
    .toSorted((a, b) => b.votes - a.votes)

  return (
    <ul>
      {visibleAnecdotes.map((anecdote) => (
        <li key={anecdote.id}>
          <p>{anecdote.content}</p>
          <span>has {anecdote.votes}</span>
          <button onClick={() => vote(anecdote.id)}>vote</button>
        </li>
      ))}
    </ul>
  )
};
```

## 💻 Installation and Running

Follow these steps to run the project locally:

1. Clone the repository:

```bash
git clone https://github.com/realNormanik/full-stack-open-state-management.git
```

2. Navigate to the application directory:

```bash
cd full-stack-open-state-management/anecdotes
```

3. Install the dependencies:

```bash
npm install
```

4. Start the JSON Server backend (it serves `db.json` at [http://localhost:3001/anecdotes](http://localhost:3001/anecdotes)):

```bash
npm run server
```

5. In a second terminal, start the development server:

```bash
npm run dev
```

The application is available at [http://localhost:5173](http://localhost:5173).

### Running the tests

The unit and component tests (Vitest) run in the `anecdotes` folder and need no running servers:

```bash
cd anecdotes
npm test
```

The Playwright tests start the application and their own JSON Server (on `anecdotes-tests/db-test.json`) automatically, so stop `npm run dev` and `npm run server` first. The `db-test.json` file must exist and contain `{ "anecdotes": [] }`:

```bash
cd anecdotes-tests
npm install
npx playwright install chromium
npm test
```

The final check verifies that the tests you wrote are real tests:

```bash
cd anecdotes-tests
npm run verify:tests-are-real
```

## 🧠 Notes

- Zustand needs no providers or reducers: a store is a hook, and the actions are plain functions that call `set`. The actions are grouped in one `actions` object, so a component can subscribe to the actions without re-rendering when the data changes.
- The state is never mutated: updates create new arrays and objects, and the list is sorted with `toSorted`.
- Sorting and filtering are derived during rendering in `AnecdoteList` instead of being stored, so the store keeps one source of truth.
- The state changes only after the backend confirms the request, so the interface shows what is really saved. Failed requests are logged and leave the state untouched.
- Notifications use a separate store, so they can be reused in other parts of the application.
- Tests mock the backend with a stubbed `fetch`, and component tests run in `jsdom`. The tests are written with `it(...)`, because the course check scripts look for `it` blocks.
- Styles are kept in `src/index.css`: design tokens in `@theme`, the dark theme via `prefers-color-scheme`, element styles in `@layer base` and reusable classes as `@utility`. The fonts are Sora and DM Sans.
- Avoid committing the `node_modules` directory.
